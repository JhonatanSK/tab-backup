# Local storage and failure model

chrome.storage.local is simple, asynchronous and has a documented 10 MB quota on current Chrome. It has no multi-record transaction across snapshot, index and retention writes. A 20-snapshot history with unusually long URLs can exceed that quota.

IndexedDB provides transactions, shared extension-origin access and a browser-managed quota. Chosen for snapshots. Its primary-key index is managed by the same transaction as each record; there is no separately maintained snapshot index that can point at an uncommitted write. All additions and retention deletions commit in one strict-durability transaction. Aborting, quota failure or worker interruption rolls back the whole transaction. Connections close after operations and on version changes. Snapshot validation occurs before mutation; unsupported stored versions block mutation and preserve originals.

chrome.storage.local holds only settings and runtime control state. The worker is the only writer. Commands are serialized, including manual capture, import, delete and restore. The in-memory queue is a concurrency mechanism, not the durable source of truth. Settings, pending deadline and restore progress survive worker disposal. A missing control-state write never claims a completed operation. During an interrupted restore, counts are a lower bound on completed browser mutations.

The Free provider limits snapshots to 20 and serialized snapshot bytes to 32 MiB. Count retention expires the oldest snapshots; exceeding the byte budget rejects the transaction instead of silently discarding more data. Actual browser quota/disk failures can occur earlier. The usage meter reports serialized snapshot bytes, not total disk allocation. Browser storage persistence can be requested by the user in Settings, without unlimitedStorage. No mechanism makes internal data an external backup; uninstall/profile deletion/disk loss can remove it. Export important files.

The first database version creates the snapshots store. The v1 data migration validates and copies fields; version 0 and future versions are rejected because no earlier public format exists. Future migrations must preserve original data, add fixture tests, and never clear on version errors.

File ingestion is bounded to 64 MiB and 100,000 total tabs, so a full supported 20 × 5,000-tab local history within the 32 MiB storage budget can round-trip. Exports use compact JSON to avoid whitespace expansion. Imports reject timestamps later than the importing machine's clock; check the system clock if a file fails for that reason. Preview includes a repository revision, rechecked inside the commit transaction. If another backup changes the library while the preview is open, the import stops and requests a fresh preview instead of silently changing the approved retention effect.
