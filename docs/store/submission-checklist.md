# Submission checklist — do not publish automatically

## Prepared in this repository

- MV3 manifest and production build, four permissions with justifications.
- English/pt_BR UI catalogs, local privacy disclosure, no external code/backend.
- Store description, privacy policy text, data-use and single-purpose statements.
- Original 16/32/48/128px extension PNG icons; 128px store icon; required 440×280 promo.
- Real extension screenshots at 1280×800 generated by E2E, using synthetic sample backups.
- Deterministic ZIP with manifest at root and SHA-256, under dist/releases after package.
- Automated test/audit evidence; manual matrix records unexecuted checks honestly.

## Human release gates still required

- [ ] Review final QA evidence in docs/qa/manual-test-plan.md, especially stable Chrome across target OSes and crash behavior.
- [ ] Complete account registration/verification and any current publisher requirements in the dashboard.
- [ ] Provide real support contact and host docs/store/privacy-policy.md on a public URL.
- [ ] Review product branding, store screenshots and descriptions; no recovery guarantees.
- [ ] Recheck live Chrome Web Store policy/disclosure fields at submission time.
- [ ] Load dist/chrome via chrome://extensions → Developer mode → Load unpacked on current stable Chrome; inspect errors.
- [ ] Re-run frozen install, lint, typecheck, tests, E2E, audit and release build from the reviewed source.
- [ ] Verify version, archive checksum and root manifest. Upload the ZIP manually.
- [ ] Enter single purpose, exact permission justifications and honest local data-handling declarations.
- [ ] Attach icon, small promo and at least one screenshot. Optional marquee is intentionally omitted.
- [ ] Select distribution/visibility and submit for review manually. Store approval is not guaranteed.

No scripts perform store publication, upload, credential creation or developer-account actions.
