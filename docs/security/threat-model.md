# Threat model and security review

Scope: local MV3 extension, extension UI, browser APIs, IndexedDB, Chrome local storage, user-selected JSON files, build dependencies, final ZIP. No server, content scripts, web-accessible resources or external messaging surface. Review date 2026-10-02.

| Threat                     | Implemented control                                                                                                                                                                                                                   | Residual risk                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Sensitive browsing records | Local storage only, no telemetry; minimal metadata; no production payload logs                                                                                                                                                        | Device/profile access can read records. Export and storage are not encrypted. Titles/URLs can reveal secrets.       |
| Malicious imported JSON    | 64 MiB pre-read limit; worker repeats validation; SHA-256 check; strict fields/types/enums; caps at 100 snapshots, 100 windows per snapshot, 5,000 tabs per snapshot, 100,000 tabs per file; bounded strings, no future-dated records | User-selected files can consume CPU/memory up to limits. Hash is not authentication.                                |
| Prototype pollution        | No recursive merge of attacker objects; reject unexpected/dangerous keys; construct own typed records                                                                                                                                 | Future migration code must follow same rules.                                                                       |
| UI XSS                     | Native createElement/textContent; imported strings never become HTML, CSS or executable links                                                                                                                                         | Browser vulnerabilities are outside application controls.                                                           |
| Dangerous navigation       | Allowlist capture/import URL schemes, HTTP(S)/about:blank restore only; remove recognizable credentials                                                                                                                               | HTTP(S) sites themselves may be malicious; user chooses restore. Unknown secret query/path/title values may remain. |
| Excessive privileges       | Four justified permissions; no host grants; incognito not_allowed                                                                                                                                                                     | tabs warning necessarily covers sensitive fields.                                                                   |
| Remote code/exfiltration   | Packaged modules only, CSP self scripts and connect-src none; no eval/new Function, external frames/scripts/fonts/images                                                                                                              | Opening restored sites causes normal browser network traffic.                                                       |
| Forged privileged command  | Only same-extension popup/options sender URLs accepted; no external message listener                                                                                                                                                  | A compromised extension context already has privileges; CSP mitigates injection.                                    |
| Worker loss/write failure  | Durable pending flag, alarm repair, strict IndexedDB transaction including retention; progress journal marks interruption                                                                                                             | Changes not yet captured cannot be recovered. Restore is not automatically resumed after ambiguity.                 |
| Bad update/migration       | Versioned validation, preserve original on failures, no clear-on-error                                                                                                                                                                | Unrecognized versions block normal UI until compatible repair/update.                                               |
| Supply chain               | Zero production npm dependencies; exact dev versions, frozen lockfile, limited build scripts, audit, artifact scan, reproducible ZIP                                                                                                  | Audit is a known-vulnerability check, not proof of dependency integrity.                                            |

## Dependency audit

Executed `npx pnpm@12.8.1 audit --json` on 2026-10-02. Registry reported 0 info/low/moderate/high/critical advisories, including development dependencies. Exact raw report: `docs/security/dependency-audit.json`. Node runtime 24.12.0; TypeScript 6.0.3 chosen because latest TS7 is outside typescript-eslint support. pnpm's install policy explicitly records the newly published @types/node release in workspace policy; it is a type-only dev dependency. Native sharp and esbuild build scripts are allowlisted for build tools only.

## Release inspection

Build checker asserts the exact permission set, incognito prohibition, expected entrypoints/locales, no sourcemaps, no content scripts/host grants/external entrypoints, and scans for dangerous code/dev markers. Manual source review checks network functions and rendering sinks. E2E exercises CSP and imported strings. No audit or scanner establishes an absolute security guarantee. Re-run audit and review the lockfile on every dependency update.
